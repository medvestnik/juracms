# Модулі та теми JuraCMS

Модулі (`modules/`) і фронтенд-теми (`themes/frontend/`) — окремі, незалежно версійовані пакунки коду. Все, що описано нижче для модулів (semver, формат ZIP, `/admin/modules → Завантажити`), справедливе і для тем один-в-один — тільки маніфест називається `theme.json` замість `module.json`, а завантаження відбувається на **/admin/themes → Завантажити тему (ZIP)** через `Theme::installFromZip()` (замість `ModuleLoader::installFromZip()`). Приклад для теми — у самому кінці файлу.

## Структура

```
modules/{ModuleName}/
  module.json      # маніфест
  bootstrap.php     # реєстрація хуків через ModuleLoader::register()
  views/            # шаблони адмінки/фронтенду модуля
```

`module.json`:

```json
{
  "slug": "gitdeploy",
  "name": "Git Deploy",
  "version": "1.1.0",
  "description": "...",
  "detect_table": "gitdeploy_log"
}
```

`slug` — унікальний ідентифікатор, використовується в БД (`jura_modules`) і в URL адмінки. Ім'я директорії (`GitDeploy`) не обов'язково збігається зі `slug` регістром — `ModuleLoader` зіставляє їх, скануючи реальні директорії, а не вгадує регістр із slug.

## Версіонування

Кожен модуль версіонується окремо від самої CMS, за [Semantic Versioning](https://semver.org/lang/uk/): `MAJOR.MINOR.PATCH`.

- **MAJOR** — зміна, що ламає сумісність (інша структура таблиць без міграції, перейменовані хуки/маршрути, які використовує кастомний форк).
- **MINOR** — нова функціональність, що не ламає існуюче (нова кнопка, нове поле з дефолтним значенням, новий необов'язковий хук).
- **PATCH** — виправлення багів без зміни поведінки ззовні.

Піднімайте `version` у `module.json` модуля щоразу, коли міняєте його файли — навіть для внутрішнього fork'у це потрібно, щоб було видно, яка версія модуля зараз стоїть на конкретному сайті (порівняно з тим, що в generic-репозиторії).

## Пакування модуля в ZIP (для завантаження через /admin/modules)

Ім'я архіву: **`{ModuleName}-v{version}.zip`**, наприклад `GitDeploy-v1.1.0.zip`.

Структура архіву — один кореневий каталог з тим самим іменем, що й на диску (`modules/{ModuleName}/`), усередині — файли модуля:

```
GitDeploy-v1.1.0.zip
└── GitDeploy/
    ├── module.json
    ├── bootstrap.php
    ├── GitDeployModule.php
    └── views/
        └── main.php
```

Версія у ЗАЗНАЧЕНОГО файлу — тільки для людини (щоб було видно у списку завантажень / у чаті, яку версію завантажуєш); сам інсталятор (`ModuleLoader::installFromZip()`) версію з імені архіву не читає — джерело правди для встановленої версії завжди `module.json` усередині.

Зібрати архів (з кореня репозиторію):

```bash
VERSION=$(php -r '$m=json_decode(file_get_contents("modules/GitDeploy/module.json"),true); echo $m["version"];')
(cd modules && zip -r "../GitDeploy-v${VERSION}.zip" GitDeploy -x '.*')
```

(запускати з кореня репозиторію; `cd modules` усередині підоболонки — обов'язково, інакше `zip -r modules/GitDeploy` кладе в архів шлях `modules/GitDeploy/...` з двома вкладеними каталогами, а не один кореневий `GitDeploy/`, і `installFromZip()` такий архів відхилить.)

Завантажте отриманий файл через **/admin/modules → Завантажити модуль (ZIP)**. Якщо модуль з такою назвою директорії вже встановлено — завантаження перезапише його файли (сама установка/налаштування в БД не чіпається), тобто це водночас і спосіб оновити вже встановлений модуль.

## Один сайт, кастомізований модуль

Якщо конкретний сайт (форк) відредагував файли модуля під себе, "Оновити зараз" (автооновлення CMS до нового релізу) **не** буде перезаписувати вже встановлену директорію цього модуля — див. `core/Updater/Updater.php::isUpdateProtected()`. Оновлення такого модуля — свідома дія: завантажити новий ZIP вручну (і за потреби перенести кастомізацію в нову версію) або відредагувати файли напряму.

Та сама логіка для тем: `themes/frontend/default/` оновлюється автоматично (це стокова тема), а будь-яка інша (кастомна) — ні.

## Приклад для теми: `theme.json` і ZIP

```json
{
  "name": "Jura Default",
  "slug": "default",
  "version": "0.2.0",
  "type": "frontend",
  "description": "...",
  "author": "Jura CMS",
  "ui_kit": "jura-ui"
}
```

```bash
VERSION=$(php -r '$m=json_decode(file_get_contents("themes/frontend/MyTheme/theme.json"),true); echo $m["version"];')
(cd themes/frontend && zip -r "../../MyTheme-v${VERSION}.zip" MyTheme -x '.*')
```

Архів — `MyTheme-v1.0.0.zip`, один кореневий каталог `MyTheme/` усередині з тим самим іменем, що на диску. Завантажте через **/admin/themes → Завантажити тему (ZIP)**.
